# 📚 중고 도서 교환 서비스

## 1. 서비스 개요

사용자가 더 이상 읽지 않는 도서를 등록하고,
다른 사용자가 해당 도서에 교환을 요청할 수 있는 간단한 **중고 도서 교환 서비스**이다.

이번 프로젝트에서는 복잡한 서비스 기능 구현보다는

**도서 등록 → 조회 → 교환 요청**

이라는 핵심 흐름을 먼저 구현하고,
이후 Docker와 AWS 환경으로 확장하는 것을 목표로 한다.

---

## 2. 핵심 기능

### 2.1 도서 등록

사용자가 교환하고 싶은 도서를 등록한다.

등록하는 정보는 다음과 같다.

- 도서 제목
- 저자
- 도서 설명

새로운 도서는 기본적으로 다음 상태로 등록된다.

```text
AVAILABLE
```

즉, 다른 사용자가 교환을 요청할 수 있는 상태이다.

---

### 2.2 도서 목록 조회

등록된 도서를 목록으로 확인할 수 있다.

목록에서는 다음 정보를 확인할 수 있다.

- 도서 제목
- 저자
- 도서 설명
- 교환 상태

또한 JavaScript를 이용하여 다음 기능을 제공한다.

- 도서 제목 검색
- 저자 검색
- 교환 상태 필터

---

### 2.3 도서 상세 조회

도서 목록에서 원하는 도서를 선택하면 상세 정보를 확인할 수 있다.

```text
도서 목록
    ↓
상세보기
    ↓
도서 상세 페이지
```

상세 페이지에서는 다음 정보를 확인할 수 있다.

- 도서 제목
- 저자
- 도서 설명
- 현재 교환 상태

교환 가능한 도서라면 **교환 요청하기** 버튼을 사용할 수 있다.

---

### 2.4 교환 요청

교환 가능한 도서에 교환 요청을 보낼 수 있다.

```text
도서 상태

AVAILABLE
    ↓
교환 요청
    ↓
REQUESTED
```

교환 요청이 발생하면 `exchange_request` 테이블에 새로운 요청이 저장된다.

```text
book_id = 요청 대상 도서
status = PENDING
```

동시에 해당 도서의 상태는

```text
AVAILABLE → REQUESTED
```

로 변경된다.

---

### 2.5 교환 요청 목록

발생한 교환 요청을 별도의 화면에서 확인할 수 있다.

현재는 다음 정보를 확인할 수 있다.

- 교환 요청 번호
- 요청 대상 도서
- 교환 요청 상태

회원 기능이 추가되면 다음과 같이 확장할 예정이다.

```text
교환 요청
├── 내가 보낸 요청
└── 내가 받은 요청
```

## 3. 전체 서비스 흐름

현재 구현된 서비스의 기본 흐름은 다음과 같다.

```text
사용자
  ↓
메인 화면
  ↓
도서 목록
  │
  ├───────────────┐
  │               │
  ▼               ▼
도서 등록       도서 선택
  │               │
  ▼               ▼
MySQL 저장      상세 조회
                  │
                  ▼
             교환 요청
                  │
          ┌───────┴────────┐
          ▼                ▼
 exchange_request        book
 PENDING 저장        상태 REQUESTED
```

---

## 4. 도서 상태

도서는 교환 진행 상황에 따라 상태를 가진다.

| 상태 | 설명 |
|---|---|
| `AVAILABLE` | 교환 가능한 도서 |
| `REQUESTED` | 교환 요청이 들어온 도서 |
| `EXCHANGED` | 교환이 완료된 도서 |

기본적인 상태 변화는 다음과 같다.

```text
AVAILABLE
    ↓
교환 요청
    ↓
REQUESTED
    ↓
교환 완료
    ↓
EXCHANGED
```

현재는 `AVAILABLE → REQUESTED`까지 구현되어 있다.

---

## 5. 교환 요청 상태

교환 요청은 다음 상태를 사용한다.

| 상태 | 설명 |
|---|---|
| `PENDING` | 교환 요청 대기 중 |
| `ACCEPTED` | 교환 요청 수락 |
| `REJECTED` | 교환 요청 거절 |

현재 교환 요청 생성 시 기본 상태는 다음과 같다.

```text
PENDING
```

교환 요청 수락 및 거절 기능은 추후 구현할 수 있다.

## 7. 현재 구현 구조

현재 로컬 개발 환경은 다음과 같다.

```text
Browser
   │
   │ HTTP
   ▼
Spring Boot
   │
   │ JPA
   ▼
MySQL
   │
   ├── book
   └── exchange_request
```

Spring Boot가 요청을 처리하고,
JPA를 통해 MySQL의 데이터를 저장하거나 조회한다.

## 8. Redis 적용 예정

도서 상세 정보는 Redis에 캐싱할 예정이다.

```text
도서 상세 요청
      ↓
Spring Boot
      ↓
Redis 확인
   ┌──┴──┐
 있음   없음
  │       │
  ▼       ▼
Redis    MySQL
반환      조회
           ↓
       Redis 저장
```

Redis Key는 다음 형식을 사용한다.

```text
book:{bookId}
```

예:

```text
book:1
book:3
book:10
```

Redis는 실제 데이터 저장소가 아니라 조회 성능 향상을 위한 캐시로 사용한다.

실제 도서 데이터는 MySQL에 저장한다.

## 9. Docker 구성 예정

로컬 기능 구현이 완료되면 Ubuntu Server에서 Docker Compose를 이용하여 다음 환경을 구성한다.

```text
Ubuntu Server
      │
      ▼
Docker Compose
      │
 ┌────┼─────┐
 │    │     │
 ▼    ▼     ▼
App   DB   Cache
 │    │     │
 ▼    ▼     ▼
Spring MySQL Redis
Boot
```

이를 통해 애플리케이션, 데이터베이스, 캐시 서버를 각각 독립된 컨테이너로 실행한다.

## 10. AWS 확장 예정

Docker 환경에서 정상 동작을 확인한 뒤 AWS 환경을 설계한다.

단계적으로 다음과 같이 확장할 예정이다.

```text
1단계
단일 서버 환경
      ↓
2단계
DB / Cache 등 관리형 서비스 분리
      ↓
3단계
다중 가용 영역 구조
      ↓
로드 밸런서
      ↓
Auto Scaling
```

이를 통해 로컬에서 만든 작은 서비스를 실제 클라우드 아키텍처로 확장하는 과정을 진행한다.

## 11. 회원 기능 추가 예정

현재 서비스에는 사용자를 구분하는 회원 기능이 없다.

따라서 현재 교환 요청에서는

```text
누가 책을 등록했는가?
누가 교환을 요청했는가?
```

를 구분할 수 없다.

회원 기능을 추가하면 다음 관계를 구성할 예정이다.

```text
회원
 │
 ├── 도서 등록
 │      ↓
 │   book.owner_id
 │
 └── 교환 요청
        ↓
 exchange_request.requester_id
```

이를 통해 다음 기능을 구현할 수 있다.

- 내가 등록한 도서 확인
- 내가 보낸 교환 요청 확인
- 내가 받은 교환 요청 확인

회원 기능은 별도 팀원이 구현할 예정이다.
