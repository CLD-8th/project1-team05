# Redis 사용 구조

## 목록 캐시

- 최신순으로 게시글을 최대 30개씩 묶어 저장하고 화면에는 10개씩 표시한다.
- 1~3페이지는 묶음 0, 4~6페이지는 묶음 1을 공유한다.
- 실제 요청된 묶음만 DB에서 조회해 저장한다. TTL은 저장 시점부터 5분이다.
- BookListItem에는 id, title, author, status, imageName만 담는다.
- BookListBlockCache는 목록 항목과 전체 게시글 수를 담는다.
- 현재 버전 키: books:list:v2:version
- 목록 묶음 키: books:list:v2:block:{version}:{block}

## 등록 및 상태 변경

새 글 등록과 상태 변경(교환 요청, 수락, 거절, 마이페이지 변경 포함) 후 버전을 변경하여 모든 이전 목록 묶음을 무효화한다. 이전 묶음 키는 TTL 만료까지 남지만 이후 요청에서 사용하지 않는다. 외부 트랜잭션 안에서는 커밋 성공 후 버전을 변경한다.

SQL로 DB를 직접 변경하면 애플리케이션의 무효화 로직을 거치지 않는다. 기존 목록은 TTL 만료 전까지 남을 수 있다. Redis 장애 시 자동 DB 대체 조회는 구현되어 있지 않다.

## 상세 조회와 조회수

도서 상세 정보는 MySQL에서 직접 조회한다. 상세 정보 캐시와 최신 30개 상세 선적재 기능은 사용하지 않는다.

조회수는 book:views:{id}, 랭킹은 book:ranking으로 관리한다. 목록 캐시 무효화는 이 데이터를 삭제하지 않는다.

## 확인 방법

앱 실행 후 4페이지에서 목록 DB 조회, 5~6페이지에서 목록 Redis HIT 로그를 확인한다. 새 글 등록 또는 상태 변경 후 다음 목록 요청은 새 버전으로 DB를 조회한다. 단위 테스트는 다음 명령으로 실행한다.

```bash
./gradlew test --tests '*BookListBlockCacheTests'
```
